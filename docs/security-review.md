## 严重

### S1 免费额度可以被人为耗尽

**先确认线上是哪个方案**：`docs/FIREBASE.md` 写的是「线上版已经改用 Blaze」，但其他地方都按 Spark 免费档在算（比如 100 人的连接上限）。请在控制台左下角看一眼（步骤 1），两种方案的风险不一样：

- **Spark**：超额度数据库就停到下个月，不扣钱。
- **Blaze**：不会停，但超出部分按量收费。被人刷流量会变成**一笔账单**。预算提醒只会发邮件，**不会自动停**，所以 Blaze 下一定要设预算提醒，并且收到邮件就处理。

**攻击者能做什么**

按 Spark 算：每月下载 10 GB，最多 100 个同时连接，超了数据库就停到下个月。按 Blaze 算：同样的流量会变成费用。

- `/stats`（现在约 63 KB，随玩家数增长）、`/boards/*`、`/ghosts/*`、`/mini/*` 不登录就能读。
- 其他路径用匿名登录也能读。
- 一个循环下载的脚本，几个小时就能把一个月的流量用完。
- 只要开着 100 条连接，所有人都连不上，排行榜也读不到。

**可能性**：低。需要有人故意捣乱，而且会写一点脚本。但一旦发生，整个月联机都不能用。

**为什么改不了根子**

免费档没有按 IP 限流，也没法在规则里限频率。匿名登录又是免费、无限的，所以把公开读改成「要登录」也挡不住。

**能做的**

1. 主人定期看用量（控制台步骤 1），发现异常早处理。
2. **App Check** 是 Firebase 的「只让真浏览器里的本游戏访问」。它用 reCAPTCHA 判断是不是真人，但 **reCAPTCHA 在中国大陆不开 VPN 用不了**。
   - 如果「强制执行」，大陆同学不开 VPN 就完全联不上（游戏会自动退回单机，排行榜快照照常看，见 PR #103）。
   - 建议：先不接。真被刷了，再接入 App Check 并强制执行，当作应急开关。接入需要改代码（加载 App Check SDK），到时候再做。
3. 应急：真被刷爆了，可以把项目升级到 Blaze（按量付费）并设预算提醒，当天恢复。每月 10 GB 以内照样免费。
4. 代码上能减少单次下载量：`stats.html` 每分钟整份读一次 `/stats` 和 4 个总榜（约 110 KB），开着的标签页一天约 160 MB。建议改成读 GitHub Actions 每 15 分钟生成的快照（M6 一起解决）。

**谁来做**：主人（控制台），代码（`stats.html` 改读快照，后续）

### S2 赛车影子能写满存储（本次已修）

**攻击者能做什么**

- 原规则里，`/ghosts/{赛道}` 的赛道名只要「像个 id」就能写。每条影子最大 40 KB。
- 同一个账号可以往几万个编出来的赛道名里各写一条，把 Spark 的 1 GB 存储写满。
- 写满以后所有人都写不进数据库：排行榜、位置、留言墙全停。

**可能性**：低（要故意），影响大。

**修法**：规则里 `/ghosts/$track` 的写入只认 `campus|bell|ridge|offroad|estate` 这 5 条赛道（`main` 和 `dev` 都只有这 5 条）。读取不变。

**以后加赛道，要在 `database.rules.json` 的这个列表里加上 id，再发布规则**，不然新赛道的影子传不上去（游戏照常玩，只是没有影子榜）。

`/mini/{游戏}` 也能编游戏名，但每条只有几十字节，要写满 1 GB 得写一千多万次，暂时不改。改的话，以后每加一个小游戏模式都要改规则，容易忘。

**谁来做**：规则（已改，需要重新发布）

## 中

### M1 头顶名字可以冒充别人（本次已修）

**攻击者能做什么**

- 以前排行榜、留言墙、展台的名字都要求和自己注册的昵称一致，但**位置同步里的名字**（`/pres` 的 `n`、旧 `/presence` 的 `name`）没有这个限制。
- 在浏览器控制台改一下，就能顶着别人的名字（比如主人的名字）在校园里走，用这个名字向别人发搭车、挑战邀请。也可以起不雅的名字。
- PR #105 的好友功能也从这里取名字。

**可能性**：中。打开 F12 就能改。

**修法**

- 规则：名字必须等于 `/users/{自己}/name`（自己注册的昵称），或者是 `游客` 加 4 位数字。
- `js/net.js`：联机时只发已注册的昵称；还没注册上（极少数注册失败、超时的情况）就发本机的「游客1234」。以前这种情况发的是本机随便写的名字。

**发布顺序**：先合并、等网站更新（几分钟），再发布规则。如果反过来，还开着旧页面、而且昵称没注册上的极少数人，这一局会掉回单机，刷新就好。

**谁来做**：代码 + 规则（已改）

### M2 排行榜分数可以伪造（加了封禁名单）

**攻击者能做什么**

成绩是浏览器自己算好写上去的。规则只能限制：

- 只能写自己的那一条
- 名字必须是自己的昵称
- 只能变高
- 不能超过上限：黑洞 100%，特技、总资产 1000 万，小游戏 100 万

在上限以内写什么数都行。现在特技榜第一名比第二名高 5 倍多，主人可以看一眼是不是正常玩出来的。

**可能性**：高。同学之间很容易有人试。

**为什么改不了根子**

真正防作弊要服务器重新算一遍成绩（Cloud Functions），免费档用不了，而且游戏是纯前端的。

**本次加的**

封禁名单 `/ban/{uid} = true`，只能在控制台里加。被封的账号不能：

- 上任何排行榜（总榜、小游戏、赛车影子）
- 改展台、贴留言、点赞、举报
- 注册昵称
- 给别人发互动消息
- 出现在别人的画面里（会掉回单机）

但删除自己的东西照常允许。操作见控制台步骤 6。匿名玩家被封了可以清浏览器数据换个新身份，但要重新起名，同学之间一般看得出来。

**谁来做**：规则（已改）；主人（发现作弊时加封禁、删成绩）

### M3 一个人可以抢注很多昵称（本次已修）

**攻击者能做什么**

- 原规则只检查「这个昵称是不是空着」，没检查「你是不是已经有一个昵称了」。
- 一个账号可以把全班同学的名字都占掉，后来的人只能用「名字 2」。

**修法**：规则要求 `/names/{昵称}` 必须是自己 `/users/{自己}/key` 指向的那一个。正常改名是一次性同时改两边，不受影响。

已经被占的名字，主人可以在控制台删掉 `/names/{那个名字}`。

**谁来做**：规则（已改）

### M4 满员排队可以被假人数卡住

**攻击者能做什么**

- 在线人数是数 `/on` 下面有几个人。正常玩家下线时由 Firebase 自动删掉。
- 但有人可以用一批匿名账号写进去，不让它自动删，人数就一直显示满员，大家都被排队。

**可能性**：低。

**修法**

- 应急（主人，1 分钟）：控制台删掉 `/on` 整个节点（在线的人几秒内会自动写回来），或者把 `/config/maxOnline` 临时改大，比如 1000，相当于关掉排队。
- 长期（代码，可以放进以后的版本）：`/on` 每 10 分钟刷新一次时间，数人数时不算 25 分钟没刷新的。代价是每人每 10 分钟多一条很小的推送。

**谁来做**：主人（应急）；代码（以后）

### M5 互动消息可以刷屏

**攻击者能做什么**

- `/social/{对方}` 只要对方在线，任何人都能一直发消息，没有频率限制。
- 对方的浏览器会收到每一条（打招呼、邀请卡片），既骚扰人，也消耗流量。

**可能性**：低到中。

**已有的保护**

- 屏蔽某人（本机生效）
- 免打扰
- 同一个人的同类邀请只排一张
- 每条消息不超过 300 字，`from` 必须是发送者自己

**本次**：被封禁的账号不能再发。规则里没法数条数，所以暂时只能这样。

**谁来做**：主人（封禁）

### M6 `/stats` 不登录就能读，能追踪某个同学的作息

**攻击者能做什么**

- `/stats/p/{uid}` 记着第一次和最后一次来的日期、总时长、用手机还是电脑。
- 总榜也是公开的，每条都带着 uid 和昵称，两边一对就知道「某某同学昨天玩到几点、玩了多久」。
- 不涉及邮箱、真名，但对被看的人不太舒服。

**可能性**：低。

**修法（后续）**

- `stats.yml` 本来就每 15 分钟读一次 `/stats` 画图。可以让它顺便生成一个不带 uid 的汇总 JSON。
- `stats.html` 改读这个汇总，然后把 `/stats` 的读权限关掉。
- 这样 S1 的流量也省了。

这件事要改工作流、统计页和规则，最好单独做一个 PR 到 `dev`。

**谁来做**：代码 + 规则（后续）

## 低

### L1 留言墙：举报和冷却

- 3 个账号（匿名的也行）举报就能把别人的便利贴藏起来。
- 先删掉再贴，可以绕过「10 分钟才能换一张」。

影响小：每人只有一张便利贴，内容规则已经挡掉链接、`<>`、6 位以上数字。

被误藏的便利贴，主人可以在控制台把 `/wallFlagN/{作者}` 改回 0。

### L2 位置同步可以刷

一个账号可以同时出现在很多格子里，或者发得很快，附近的人都要收。

游戏画别人有上限（低画质最多 3 个完整模型、10 个模型、4 个名字），所以不会卡死，主要是费流量（归到 S1）。被封禁的账号已经不能写位置。

### L3 成绩时间由浏览器写

总榜的 `ts` 用的是本机时间，可以写成很早，影响两件事：

- 同分时谁排前面
- 注册制之前的老玩家按先后编号

影响很小。改成服务器时间要同时改客户端，暂不改。

### L4 第三方脚本没有完整性校验（PR 到 `dev` 已加）

- three.js 从 jsdelivr 加载，Firebase SDK 从 gstatic 加载，都没有 SRI。万一 CDN 被篡改，恶意脚本能拿到玩家的登录状态和存档。
- 版本号都是写死的，文件不会变，所以加 SRI 没有副作用。
- 已在 `dev` 的 PR 里给这 5 个文件加了 `integrity`。
- 以后升级 three.js 或 Firebase 版本，要一起换 hash（写在代码注释里了）。

### L5 没有 CSP

- 这次把所有「别人的文字进页面」的地方都看了一遍：头顶名字、排行榜、留言墙、展台、互动菜单和卡片、好友（#105）、主线（#102 / #106）、电台。
- 都用了 `textContent`、canvas 文字或者转义函数（`esc` / `wlEsc` / `scEsc` / `dmEsc` / `ofEsc`）。
- 网址参数只有 `?netmeter`（只统计流量），`postMessage` 只有电台离线测试用的 BroadcastChannel（同源、检查过字段）。**没发现 XSS。**

CSP 是「万一有漏洞也不让外来脚本跑」的第二道保险。GitHub Pages 不能加响应头，但可以在 `index.html` 里加 `<meta http-equiv="Content-Security-Policy">`。

这次没加，原因：

- 页面里有内联脚本。
- Firebase 在某些网络下会退回「长轮询」，从数据库域名加载脚本。
- Google 登录要开 `firebaseapp.com` 的弹窗和 iframe。
- 规则写漏一条就会有一部分人联不上，而且只有连正式库才测得出来（这次不允许）。

如果要加，建议先在 `dev` 配一个测试用的 Firebase 项目（`js/firebase-config.preview.js`），在预览版上把联机、Google 登录、排队都测一遍再发。大致是：

```
default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://www.gstatic.com https://apis.google.com https://*.firebasedatabase.app;
connect-src 'self' https://*.googleapis.com https://*.firebasedatabase.app wss://*.firebasedatabase.app; frame-src https://*.firebaseapp.com https://accounts.google.com;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data: blob:; media-src 'self' blob:
```

### L6 预览版和正式版同一个网址来源

- `/preview/` 和正式版都在 `izhengjy.github.io`，主人名下其他 GitHub Pages 项目也是这个来源。同一来源的页面能读彼此的 localStorage 和 Firebase 登录状态。
- `preview-guard.js` 给预览版的键加前缀，是防「不小心覆盖存档」，不是安全隔离。
- 现在 `dev` 只有主人在推、预览版离线，`preview-cheats.js` 有三道关：`XMUM_PREVIEW`、路径 `/preview/`、连的是正式项目就不开，还把提交成绩换成空操作。所以风险低。
- 但 `dev` 分支没有保护（见 GitHub 部分）。
- 以后如果要给更多人推 `dev` 的权限，预览版最好换到另一个域名（比如单独的仓库加自定义域名）。

### L7 公用电脑上退出 Google 后存档还在

- 「退出 Google」后会变成新的游客，但本机的进度和昵称还在。
- 在机房电脑上，下一个人打开会接着这份进度玩。如果他登录了自己的 Google，这份进度会传到他的云存档。
- 不涉及隐私数据，只是进度被别人拿走。
- 可以以后在退出时问一句「要不要清掉这台电脑上的进度」。

## 已经做对的

**数据库**

- 根节点默认不能读写，每个节点都单独开放。
- 每个能写的地方都检查 `auth.uid === $uid`，只能写自己的。
- 对象节点都有 `$other: false`，不能夹带别的字段。
- 字段都有类型、长度、格式检查。
- 排行榜和展台的名字必须是注册昵称，成绩只能变高。
- 云存档 `/saves` 只有本人能读，只有 Google 账号能写。
- 数据库里**没有存邮箱和 Google 名字**，这些只留在玩家自己的浏览器里显示。

**前端**

- 所有别人的文字进页面都做了转义或用 `textContent`（见 L5）。
- 留言墙规则挡掉了链接、尖括号、手机号；昵称只允许中文、字母、数字和几个符号。

**省额度**

- 位置按 100 米分格，只听附近 9 格。
- 后台、开场画面闲置会断开连接。
- 有人数上限和排队。
- 影子榜只读前 8 名，排行榜最多读 100 条。

**预览版**

- 部署时换成离线配置，永远不连正式库。
- localStorage 加前缀；作弊工具有三道关。

**API key**

- 浏览器 API key 已经限制了来源网址。这次本地测试时确认了 `localhost` 会被挡（`requests-from-referer-...-are-blocked`）。
- 之前关掉的 secret scanning 告警处理得对：Firebase 网页 key 本来就是公开的，安全靠规则。

**GitHub**

- `main` 有分支保护（管理员也要走 PR，不能强推、不能删）。

### 数据库备份（PR #107）

**怎么存的**

- 工作流 `.github/workflows/db-backup.yml`，每 12 小时跑一次，也可以手动点「Run workflow」。
- 密钥：
  - Secret `FIREBASE_BACKUP_SA`：Google 服务账号的 JSON 密钥。
  - Variable `BACKUP_PUBLIC_KEY`：主人的 gpg **公钥**，不是秘密。
- 存放位置：整库下载下来，在内存里用公钥加密成 `.json.gpg`，存成本仓库的 **Actions Artifact**，保留 14 天。
  - 公开仓库的 Artifact 谁都能下载，但下载到的是加密文件，只有主人的**私钥 + 口令**能解开。
  - 私钥按说明放在 U 盘 / 密码管理器里，不在 GitHub 上。

**审查结论：设计是安全的**

- 明文不落盘、不打印、不上传。
- 工作流只有 `contents: read`，只能由定时任务或手动触发，PR 里的代码拿不到 secret。
- 第三方 action 用 40 位 commit SHA 固定。
- 测试工作流不用任何 secret。

**主人要注意的**

1. **服务账号角色尽量只用 Viewer**（只读）。
   - #107 说 Viewer 能不能通过 REST 读数据还不确定，不行就换 Admin。
   - Admin 能**改、删**整个数据库。如果真要换，这个密钥就和数据库主人的钥匙一样重要：每年在 Google Cloud 控制台轮换一次，不用备份了就立刻删掉。
2. **私钥丢了，所有备份都打不开**；私钥连同口令一起泄露，所有备份（含云存档）都会被解开。私钥和口令分开放。
3. 谁能改仓库的 Variable，谁就能把公钥换成自己的，之后的备份就是给他加密的。现在只有主人有仓库权限，所以没问题；以后加协作者要记住这一点。
4. 每次备份都要下载整个数据库，按 #107 的估算占每月流量 1%～8%，归到 S1 一起看用量。

## 只有主人能做的控制台操作

### Firebase 控制台（console.firebase.google.com → xmum-campus）

**1. 确认方案、看用量（每周看一眼）**

- 左下角写着「Spark」还是「Blaze」。如果是 **Blaze**，马上做步骤 4 的预算提醒。
- 左边「构建 → Realtime Database」→ 上面「用量」标签。
- 看「下载量」（每月 10 GB）、「连接数」（最多 100）、「存储」（1 GB）。
- 下载量曲线突然变陡、存储突然变大，就是有人在刷。

**2. 发布这次的规则（合并 `main` 的 PR、网站更新几分钟以后）**

- 「Realtime Database → 规则」→ 把仓库里 `database.rules.json` 的全部内容粘贴进去 → 「发布」。
- 发布前可以点「规则游乐场」模拟几次（不会写数据）：
  - 「身份验证」选「已通过身份验证」，提供方选「匿名」，UID 填 `test1`。
  - 位置「`/ghosts/fake1/test1`」，类型「设置」，数据随便填 → 应该**拒绝**（赛道不在列表里）。
  - 位置「`/pres/12_12/test1`」，类型「更新」，数据 `{"n": "别人的名字"}` → 应该**拒绝**。
  - 同一个位置，数据 `{"n": "游客1234"}` → 这一项单独模拟会因为缺少 `p`、`t`、`m` 被拒，属于正常；想看它通过，要把四个字段都填上。
  - 位置「`/boards/stunt/test1`」，读 → 不用登录也**允许**（公开榜）。

**3. App Check（先别开，留作应急）**

- 「构建 → App Check」。真被刷流量时再用：注册 reCAPTCHA v3，然后需要改代码接入，再点「强制执行」。
- 代价：大陆不开 VPN 的同学会联不上（自动单机）。

**4. 预算提醒（Blaze 必做）/ 应急升级（Spark）**

- 已经是 Blaze：打开 Google Cloud 控制台「结算 → 预算和提醒」→「创建预算」，项目选 `xmum-campus`，金额比如 RM 10，提醒比例 50% / 90% / 100%，发到自己邮箱。
  - 注意：预算**只提醒、不封顶**。收到邮件就去看用量，如果是被刷，先按步骤 3 开 App Check。
- 还是 Spark，被刷爆、数据库停了又不想等到下个月：左下角「升级」到 Blaze，同时按上面设预算提醒。

**5. 满员被卡住（大家都在排队，但实际没几个人）**

- 「Realtime Database → 数据」→ 找到 `on` 节点 → 右边的「⋮」→ 删除。在线的人几秒内会自动写回来。
- 或者把 `config/maxOnline` 临时改成 `1000`。

**6. 封禁作弊或骚扰的人**

1. 在「数据」里找到他的 uid：排行榜 `boards/stunt` 下面的每个键就是 uid，旁边的 `name` 是昵称。
2. 在根节点点「+」：名称 `ban`，然后在 `ban` 下面加一项，名称填那个 uid，值填 `true`。
3. 再删掉他的假成绩：`boards/xxx/{uid}`、`mini/xxx/{uid}`、`ghosts/xxx/{uid}`、`showcase/{uid}`。
4. 解封：删掉 `ban/{uid}`。

**7. 匿名注册限额（可选，不建议调太低）**

- 「Authentication → 设置 → 注册配额」默认每个 IP 每小时 100 个新账号。
- 学校 Wi-Fi 很多人共用一个出口 IP，开学新同学集中进来时可能超过，**不要低于 100**。

**8. 授权网域（可选）**

- 「Authentication → 设置 → 已获授权的网域」只需要 `izhengjy.github.io` 和 `xmum-campus.firebaseapp.com`。
- `localhost` 可以删掉（API key 已经挡住了 localhost，删了更干净）。

### GitHub（github.com/iZHENGjy/xmum-campus → Settings）

**9. 保护 `dev` 分支**

- 「Branches → Add branch ruleset」（或 Add rule），分支名 `dev`。
- 勾选「Restrict deletions」和「Block force pushes」。
- 不用勾「Require a pull request」（自己平时合并 PR 不受影响）。

**10. 打开 Dependabot 提醒（可选）**

- 「Code security → Dependabot alerts → Enable」。

**11. 限制能用的 Actions（可选）**

- 「Actions → General → Actions permissions」选「Allow iZHENGjy, and select non-iZHENGjy, actions and reusable workflows」，勾「Allow actions created by GitHub」。
- 现在只用 GitHub 官方的 Actions，不受影响。
