# 改装车间

代码：`js/42-tuning.js`（道具、零件目录、装到车上）和 `js/93-tuning-ui.js`（界面、施工队列、道具发放、存档）。

## 玩法

- 买车不用等，改装要等。在「XMUM 车行 → 改装车间」点零件就能在 3D 里预览（拖动转视角，滚轮缩放），点「下单施工」扣金币和道具，零件进施工位按真实时间计时。
- 存的是完工的时间戳，关掉游戏也照样走。完工时提示一次，车行按钮上挂「可提车」，回改装车间点「提车」就装上。
- 施工中的车照样能开，只是新零件还没装。完工没提车的也占着施工位。
- 默认 1 个施工位，第二个用 RM 800 解锁。
- 加急：每分钟 RM 12，或每 20 分钟 1 张改装图纸。没有任何真钱加速。
- 新玩家：第一次打开改装车间送一份开张礼包（轮毂坯件 ×3、赛车漆料 ×2、碳纤维板 ×1、霓虹灯管 ×1，老玩家每 4 个成就再送 1 张图纸），第一单 30 秒完工。
- 造好的零件属于那辆车，之后随时免费换装 / 换回原厂。
- 别的玩家能看到你自己的车上的改装（开着它的时候）。

## 接口：给玩家发道具

```js
XParts.grant(id, n, reason)   // 发 n 个（默认 1），reason 显示给玩家看，比如 '竞速金牌'；返回新的数量，id 不认识或 n <= 0 时返回 0
XParts.medal(medal, reason)   // 按奖牌发：0 金 → 涡轮，1 银 → 碳纤维板，2 铜 → 赛车漆料，3 及以上（没牌）不发
XParts.count(id)              // 现在有几个
XParts.list                   // 道具定义（id、name、rm 估值、from 说明）
```

- 每发一次，HUD 上方（改装车间打开时在 3D 画面底部）冒一个小条「+1 碳纤维板 · 猴子大战金牌」，最多同时 3 条。
- 页面里没有 `js/93-tuning-ui.js` 时 `window.XParts` 不存在，调用前判断一下：`if (window.XParts) XParts.medal(medal, '竞速' + GX_MEDAL[medal]);`
- 新玩法建议：一局结束按奖牌调 `XParts.medal`；特别难的成就或一轮清空再额外发一张 `plan`。记得把来源补进 `js/42-tuning.js` 的 `TN_PARTS[].from`，背包里会显示给玩家。

### 已经接好的（dev 上的玩法）

都是在 `js/93-tuning-ui.js` 里包住各玩法自己的结算函数，调完原函数再发，没改那些文件：

| 玩法 | 怎么接的 | 掉落 |
|---|---|---|
| 外卖（`js/50-missions.js`） | 每帧看 `prog.life.deliv` 涨没涨 | 轮毂坯件 ×1 / 单 |
| 得来速（`js/89-outskirts-play.js`） | 同上，同时 `prog.best.o_dt` 也涨了 | 轮毂坯件 ×1 + 赛车漆料 ×1；夜里再加霓虹灯管 ×1 |
| 偷外卖的小偷 | 包 `thCatch` | 涡轮 ×1 |
| Bell 通缉榜清空 | 同上，`o_thief` 刚好是 `TH_LIST.length` 的倍数 | 改装图纸 ×1 |
| 猴子大战（`js/89-swing-monkeys.js`） | 包 `mkWarEnd`，只算赢的 | 碳纤维板 金 ×3 / 银 ×2 / 铜 ×1 |
| 宿舍撤离（`js/89-dorm.js`） | 包 `dmFinish`，带出东西才算 | 霓虹灯管 ×1；带出 RM 150 以上再加碳纤维板 ×1 |
| B1 小游戏（`js/91-arcade.js`） | 包 `mgFinish`，按奖牌 | `XParts.medal` |
| 挑战赛（`js/85-activities.js`，含山梁拉力） | 包 `gxFinish` | 拿牌赛车漆料 ×1，金牌再加碳纤维板 ×1 |
| 成就 | 包 `unlock`，第一次解锁才算 | 改装图纸 ×1 |

还没接（在别的分支）：竞速（PR #30）、KIP 大乱斗、期末卷。合并后在自己的结算里加一行 `XParts.medal(...)` 或 `XParts.grant(...)` 就行。

### 加零件

在 `js/42-tuning.js` 的 `TN_ITEMS` 里**往对应槽的末尾**加一行。联机外观字符串（`/looks` 里的 `tk…`）按「槽的顺序 + 零件在槽里的序号」编码：

- 槽只能加在 `TN_SLOTS` 的末尾，零件只能加在槽的末尾，不能删、不能调顺序，否则别人看到的会错位。
- 每个槽一个 36 进制字符，所以一个槽最多 36 件。
- 新的外形要在 `tnBody`（车身件）或 `tnWheelGeo`（轮毂）里画出来。车上的位置由 `tnAnchors` 用射线从车身外壳上量出来，五辆车行的车都能用。

### 性能字段（先不生效）

每件零件有 `perf: {acc, maxV, grip}`（比例，比如 `.02` = +2%）。`js/42-tuning.js` 的 `TN_PERF = 0`，所以现在只改外观。主人决定要性能改装的话，把它改成 1 就按装着的零件加成（`js/93-tuning-ui.js` 包在 `tunedT` 外面），数值再调。

## 存档

`localStorage['xmum-tune-v1']`（Google 登录的人跟其他 `xmum-*` 键一起云同步）：

```js
{
  inv: {rim, lacq, cf, turbo, neon, plan},           // 道具
  cars: {p911: {own: ['rim.forged', …], fit: {rim: 'forged', …}}},   // 每辆车造好的零件和现在装的
  jobs: [{k: 'wing.gt', kind: 'p911', t0, t1, told}], // 施工位，t1 = 完工时间戳
  bays: 1 | 2, first, kit, spent
}
```

## 总资产

`assetSource('carmods', …)`：造好的零件和施工位里的零件按「金币 + 用掉的道具估值」，背包里的道具按估值，第二个施工位 RM 800。下单只是把现金换成零件，总资产不变；加急花的钱和图纸不算资产。

## 联机

开着自己的车时，`XWard.lookStr()` 后面多一段 `tk` + 每槽一个字符（共 18 个字符），总长超过 120 就不带这段。`js/net.js` 画别人的车时调 `tnApply(c, tnFromToken(look))`。字符只用 `[a-z0-9]`，现有的 `/looks` 规则就能通过，**不用重新发布数据库规则**。

## 测试开关

预览版（`/preview/`）和本地测试页才有，正式版没有这个对象：

```js
XTuneDebug.ff()          // 施工全部完工；ff(10) = 快进 10 分钟
XTuneDebug.give('cf', 5) // 发道具（会显示「· 调试」）
XTuneDebug.kit(10)       // 每样道具各发 10 个
XTuneDebug.reset()       // 清空改装存档并刷新
XTuneDebug.state         // 看存档
```

判断方法：域名不是 `*.github.io`，或者路径里有 `/preview/`。
