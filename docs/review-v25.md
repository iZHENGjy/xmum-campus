### 「现在很卡」：v24 和 v25 对比

同一台电脑，「标准」档，分辨率固定在 1258×702，停掉游戏循环后量渲染，取 5 次的中位数：

| 地点 | 显卡时间 v24 → v25（ms） | draw call v24 → v25 |
|---|---|---|
| A3 | 20.6 → 19.7 | 320 → 316 |
| Bell Avenue | 17.9 → 17.8 | 308 → 308 |
| KIP | 19.5 → 19.4 | 384 → 385 |
| D6 | 13.1 → 14.7 | 125 → 158 |

在 A3 往前走，每帧的 JS 时间（两次平均）：v24 7.8 ms（其中 three.js 准备绘制 5.9）→ v25 9.6 ms（7.3）。也就是：
- **显卡负担没变**，v25 主要是 **CPU 多了约 1.8 ms / 帧（+23%）**。这部分分散在 v25 新加的很多系统里：校园作息的行人、路上事件、隐藏跳台、新地图上多出来的约 115 个可见物体。没有哪一个特别重。
- 色调映射每帧约 0.25 ms。阴影重画频率和 v24 一样（每 2 帧一次）。
- 地图外藏起来的房间（游戏厅、KLIA、房子……）占了一半节点，但每帧算它们的矩阵只花不到 0.1 ms，不值得改。
- 手机 CPU 大约慢 4–5 倍，所以手机上可能每帧多 7–9 ms，这可能就是「卡」。已经做的：HUD 不再每帧写 DOM、房子标牌不再每帧格式化价格（都在 #142）。
- 联网时其他玩家的车和人这部分，离线页测不到。

- 流畅档在每个地点的 draw call 和三角形都比标准少，没有哪里反而更重。帧时间里有动态分辨率在调，所以不完全是同一个像素数在比。
- JS 堆：游戏中 160–230 MB（同一个页面开了很久、反复进出场景以后最高 366 MB）。
- 加载：119 个请求，约 5 MB（本地服务器没压缩：JS 3.2 MB、字体 1.46 MB / 21 个、three.js 150 KB）。GitHub Pages 会 gzip，JS 实际下载大约是三分之一。
- 脚本解析到能点（本地）：流畅 1.2 秒、标准 1.8 秒、高清 2.8 秒。
- 进出场景：KLIA 来回 3 次、宿舍 3 次、车队车库 3 次、卡丁车比赛 6 场，内存没有一直涨（KLIA 第一次留下一些缓存的模型，之后每次 +6 个几何体，可以忽略）。
- 「高清夜里改像素比后整屏变白」：电脑（动态分辨率 0.6→1、来回切画质）和手机（像素比 1.5 / 2、竖屏转横屏）都**没复现**，泛光正常。怀疑是测试脚本手动推帧和真实帧混在一起，把光照的渐变算爆了。
